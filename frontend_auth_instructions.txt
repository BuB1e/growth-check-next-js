# Frontend Authentication Implementation Guide (Better-Auth)

The backend has recently been migrated to use `better-auth` for authentication. Here is what you need to know to implement the frontend integration based on the latest backend changes.

## 1. Supported Authentication Methods
The backend now natively supports the following login methods:
- **Email & Password**
- **Google** (Social)
- **LINE** (Social)
- **Facebook** (Social)

## 2. Critical Cookie & CORS Configuration
The backend session management now utilizes cookies with specific security attributes:
- `httpOnly: true`
- `secure: true`
- `sameSite: "none"`
- `crossSubDomainCookies: true`

**Action Required on Frontend:**
- Every HTTP request (fetch, axios, etc.) made to the backend API that requires authentication **MUST** include credentials so that the session cookies are sent back and forth.
  - For `fetch`: include `credentials: "include"`
  - For `axios`: include `withCredentials: true`
- The backend relies on a new environment variable `BETTER_AUTH_CORS` for trusted frontend origins. Ensure your frontend application's URL (e.g., `http://localhost:5173` or your production domain) is communicated to the backend team so it can be added to the allowed CORS origins list.

## 3. Better-Auth SDK Integration
If you are using the Better Auth client SDK (e.g., `@better-auth/react` or vanilla client library), you should configure it to point to the backend's base API URL.

If you are calling the backend manually, the backend's `UserService` explicitly exposes the following login wrappers:
- `signInEmail(email, password)`
- `signInGoogle()`
- `signInLine()`
- `signInFacebook()`
- `signOut()`

*(Please coordinate with the backend engineer on the exact route paths if they have been wrapped in custom endpoints, or use the standard `/api/auth/*` endpoints provided by better-auth).*

## 4. User Schema Reminders
When implementing the registration or fetching user data from the session:
- `firstName` is a **required** field.
- `lastName` is an optional field.
- The `role` will default to `"USER"`.
