# Admin Frontend Updates (User Create Status)

The backend has been updated to fully support the frontend requirements for the "คำร้องขอเปิดบัญชีผู้ใช้งาน" (Account creation requests) page. Here is how to use the updated APIs:

## 1. Fetching & Filtering Requests
**Endpoint:** `GET /user-create-status`

You can now use the following query parameters to filter and search the list:
- `status` (string): Filter by request status. Values: `WAITING`, `APPROVED`, `REJECTED`.
- `role` (string): Filter by user role. Values: `ADMIN`, `USER` (Staff), `HEAD`.
- `q` (string): Search text. The backend will automatically perform a case-insensitive search across the user's `firstName`, `lastName`, `email`, and `userId` (identification_id), as well as the request's `rejectReason`.

**Example Usage:**
To get `WAITING` requests filtered by `USER` role and searching for "John":
```http
GET /user-create-status?status=WAITING&role=USER&q=John
```

## 2. Approving / Rejecting Requests
**Endpoint:** `PATCH /user-create-status/:userId`

The update payload now allows the Admin to assign a role and modify the requested area (`teamId`) at the exact time of approval.

**Body Parameters:**
- `requestStatus` (string): `APPROVED` or `REJECTED`.
- `rejectReason` (string): Required if rejecting.
- `updatedBy` (string): The UUID of the admin performing the action.
- `role` (string, optional): The assigned role for the user (`ADMIN`, `USER`, or `HEAD`). Defaults to `USER` in DB if not provided.
- `teamId` (number, optional): The assigned tracking area/team ID. Admin can change this from what the user originally requested.

**Example Approval Payload (Assigning Role and Area):**
```json
{
  "requestStatus": "APPROVED",
  "updatedBy": "admin-uuid-here",
  "role": "USER",
  "teamId": 2
}
```

**Example Rejection Payload:**
```json
{
  "requestStatus": "REJECTED",
  "rejectReason": "Incomplete information provided.",
  "updatedBy": "admin-uuid-here"
}
```
